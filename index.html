Founding Product Engineer

Ubik — AI-native workspace for supply chain operators

One of the earliest engineers on the team, with technical ownership spanning cloud infrastructure, agentic AI/RAG systems, ERP integrations, and SOC 2 compliance. Ubik serves enterprise customers including AZ Gems International, Sandhya Marines, and Wanaka.

  • Built the Dynamics 365 Finance integration from scratch — a full FastAPI service (Ubik-d365) with OData API sync, a Bronze/BigQuery data architecture, and Cloud Run deployment via Workload Identity Federation, covered by 173 unit and 46 integration tests.
  • Designed ubik-zoho, a backend on a Bronze/Silver medallion architecture with 7 sync modules and write-action endpoints, plus a separate Zoho Analytics API integration.
  • One customer, AZ Gems, runs over 80,000 vendor bills through their ERP sync — and at that volume, the pipeline began timing out and quietly dropping updates, the kind of failure that doesn't surface until finance is reconciling numbers that don't match. I split it into a dedicated erp_bills table with dual cursors and hard page-count limits, so scale stopped being a landmine.
  • Own technical delivery across SOC 2 controls — encryption at rest, monitoring & alerting evidence across 7 repos, RBAC evidence spanning GCP IAM/GitHub/AWS IAM, environment separation, input sanitization (found and fixed a critical SQL injection via Semgrep), backup & DR, and network access control via a NetBird WireGuard mesh. Our most recent third-party pentest returned no Critical or High findings.
  • Ran a full architectural audit of the Ubik codebase, surfacing a partially migrated memory system, dead vector-store code, and an authentication bypass risk on an email endpoint — since triaged and fixed.
  • Led Google OAuth verification for Ubik's Gmail/Calendar scopes, reducing the requested scope count and rewriting per-scope justifications.

SOC 2 Copilot

built in a day

An agentic infrastructure-compliance scanner, built to show founders what an automated compliance review can look like — not a generic take-home exercise.

  • Pipeline: infra config (Terraform state and/or a live cloud API) → vector retrieval over SOC 2/CIS reference docs → a reasoning agent → a self-check pass → a GitHub PR with findings, traced end to end in Langfuse.
  • Built two versions of the reasoning stage: a fixed pipeline and an agentic, tool-calling version, as alternate demo paths.
  • Runs on Gemini's free-tier API, with a small frontend to review findings.
